# 阶段一：数据闭环（2026-11-20）

- 基础：`dfaac5a`（UI v2）之后的工作区
- 范围：JSON 导出/导入、备份恢复入口、回收站 30 天清理、暂停状态持久化、便携数据目录
- 不变：离线、无遥测、无键盘钩子；`SendInput` 后不自动重试，结果不确定时只复制

## 交付

| 项 | 实现 |
| --- | --- |
| 导出 | 设置 → 数据 → “导出…”，`GetSaveFileNameW` 选择路径，写出格式化 `DataFile` JSON |
| 导入 | “导入…”选择文件；合并/替换二选一；20 MB、10,000 短语、1,000 分类上限 |
| 导入校验 | schema 1..=1；分类 ID 唯一、名称去空白后非空且不区分大小写唯一；短语 ID 唯一、正文按现有规则校验、分类引用必须存在、活动标题不区分大小写唯一；统一重建 `search_blob`；导入 revision 归零，防止 `u64::MAX` 溢出 |
| 合并 | 分类按名称 Unicode 小写匹配；ID 冲突改发新 ID；活动重复标题跳过并计入 `snippets_skipped`；分类引用重映射 |
| 替换 | 先完整校验，再走 `save_data` 原子写；写盘失败回滚内存，旧数据由既有备份轮转保留；保留本地 revision 下限 |
| 备份恢复 | “恢复备份…”默认打开 `backups/`，二次确认后按替换导入；最近 5 份备份仍由存储层轮转 |
| 回收站清理 | 启动时 `purge_expired(30)`，仅删除 `deleted_at` 超过 30 天且为规范 UTC 时间的行；偏移/空串/畸形时间保留，失败只记日志不阻塞启动 |
| 暂停持久化 | 托盘暂停/恢复写入 `Settings.paused`；启动时保持暂停、不注册热键，托盘提示同步；`--selftest`/`--bench` 诊断模式忽略暂停 |
| 便携模式 | 可执行文件旁存在 `portable.txt` 或 `portable` 文件时，数据、备份、日志、截取全部写到 `<exe>\data` |
| 文案修正 | 管理窗口“排序权重”改为“置顶”，与实际行为一致 |

## 安全与失败路径

- 导入文件先查元数据，再以 `take(20 MB + 1)` 限量读取；随后才解析和校验。
- 只读模式拒绝导入/清理，返回 `read_only`。
- 替换与合并在内存副本上完成，`save_data` 失败即回滚，不改变当前会话数据。
- 备份在替换成功后才裁剪，替换失败不会消耗最老恢复点。
- 备份恢复使用与替换导入相同的校验和回滚路径，不直接覆盖 `data.json`。
- 管理窗口重开时，干净编辑器从存储刷新；未保存草稿保留，分类使用稳定 ID，避免被导入后的分类顺序重映射。

## 残留

- 导入成功后不热刷新已打开的面板/管理窗口；窗口保持打开期间导入，保存旧草稿仍可能覆盖同 ID 内容（状态文案提示重开）。
- 回收站“清空”仅有存储 API，未加管理窗口按钮；30 天自动清理已生效。
- 导入导出仅支持 QuickPhrase JSON，不支持纯文本/CSV。
- 便携模式需手动放置标记文件；没有设置页开关。
- 导出直接写用户选择的目标文件，失败可能留下截断文件；不影响库数据。
- `Settings.paused` 仍无 `#[serde(default)]`：该缺口在基线已存在，正常升级链路始终写出该字段；手工删除键的旧配置会进入恢复/只读流程。
- 真实跨应用输入矩阵、IME 与 125/150/200% 视觉矩阵仍待交互桌面验证。
