## 自检发现的内部矛盾

### C1（blocker）Document 级元素：允许还是拒绝

- §5.5 能力矩阵：`UIA Document（整页）` → “仅单行”。
- §7 G7：`Document 整页` → “拒绝”。

同一对象两个结论。按 B1/M11 的保守原则，应统一为“只复制”。

### C2（major）换行策略与 E1 冲突

- D5：所有换行统一归一为 CR。
- D23 / §6.3：浏览器若 E1 通过，改用 LF。

需要把 D5 改成“默认 CR，浏览器实验通道 LF”，否则两处互相否定。

### C3（blocker）用户规则可绕过区域判定

- §6.2 `rules-user.json` 示例：`{ "exe": "Code.exe", "region": "TEXT_EDITOR" }`。
- §6.2 规则又写“安全硬规则不可覆盖”，但硬规则清单没有包含“区域判定”。

结果：用户可以把混合宿主标成编辑器，多行进集成终端执行。必须改成：用户只能收紧策略，不能放宽多行；区域升级只能由 M0 验证过的运行时标记决定，不能按 exe 写死。

### C4（minor）前台事件钩子声明未落地

- §2.1 声明使用 `EVENT_OBJECT_FOCUS` 观察焦点。
- v3 已删除焦点缓存设计，正文没有使用该钩子。

要么删掉声明，要么标为 M2 可选优化。

### C5（minor）T12 引用了不存在的缓存

- T12 写“焦点缓存/快照过期（若实现缓存）”，但 v3 明确不做缓存。

应改为“快照超时后不复用”。

### C6（minor）M0-4 持有 T7/T8，实际属于 M0-2

T7（UIA 延迟）与 T8（UIA 阻塞）是捕获层测试，不是注入层。归属写错，不影响门禁但会误导实施。

## 结论

v3 存在 2 个 blocker（C1、C3）与 1 个 major（C2）的内部矛盾，预计三家复核会命中至少其中两条。v4 必须修掉后再进 M0。
