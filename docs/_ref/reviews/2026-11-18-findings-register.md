# QuickPhrase 待闭环问题清单（focused review 输入）

> 来源：v1 独立复核报告（B1–B3、M1–M10）+ v2 定向增量复核（B4、B5、M11–M14）。
> 本清单只保留**问题主张与必改要求**，用于判断 v3 是否闭环；不包含对 v3 的预判。
> 复核对象：`docs/_ref/final-plan.md`（v3）。

## 判定词

- `CLOSED`：v3 有明确、可执行的条款，且不存在与其它条款冲突。
- `PARTIAL`：方向对，但缺可执行细节、缺验收、或与其它条款矛盾。
- `OPEN`：未处理，或只换了措辞。

## 清单

### B1（Blocker）控件身份
主张：`TEXT / NON_TEXT / UNKNOWN` 只说明控件能否接收文字，不证明是快照时的同一个控件；同一页面 A→B 切换时 HWND/PID/控件类型都可能不变。
必改：快照捕获目标 UIA 元素身份，恢复后用 `CompareElements` 或 RuntimeId 比较；只能识别到宿主容器时不得放行；页面重建导致身份变化时降级只复制。

### B2（Blocker）零写入
主张：返回事件数异常、发送后焦点变化，都属于输入已启动后的异常，无法保证此前字符未进入宿主。
必改：区分输入前拒绝与输入后不确定；不得宣称零写入或“已完整成功”；不得自动重试。

### B3（Blocker）终端粘贴
主张：终端粘贴多行本身可能执行命令，不能把“没用 Unicode”当作安全。
必改：MVP 对终端含换行一律只复制，不代替用户粘贴；终端识别不能只看命令进程名。

### B4（Blocker）UIA 捕获竞态
主张：WM_HOTKEY 只同步存 HWND、UIA 异步排队，面板激活后再 `GetFocusedElement()`，拿到的是面板自己的搜索框。
必改：原始 UIA 元素必须确实在面板夺取焦点之前采到；晚于激活且无法证明原始上下文的快照禁止冒充；不得用重新查询当前焦点补快照。

### B5（Blocker）嵌入式终端
主张：`Code.exe` 同时承载编辑器和集成终端，按 EXE 分类会把终端当编辑器注入多行 CR。
必改：安全策略以“实际输入目标区域”为单位，不以 exe 白名单放行；不可辨认的子区域多行保守降级复制。

### M1（Major）捕获时序与性能
主张：热键回调 `<1ms` 与 UIA 50ms 预算冲突；面板夺焦点后再取焦点会拿到面板自身。
必改：身份快照在面板获得焦点前完成；UIA 放独立线程；分开衡量热键处理与原目标上下文就绪耗时。

### M2（Major）前台代数
主张：正常流程本身产生“原应用 → 面板 → 原应用”，不能把所有前台变化都判为第三方干扰。
必改：定义允许序列与应取消的第三方切换；测试通知抢焦点、模态框、同应用切标签。

### M3（Major）前台恢复
主张：`SetForegroundWindow` 受激活限制；不能只写“300ms 内恢复”。
必改：恢复后再次验证前台与焦点控件；失败只复制；不为延迟目标牺牲正确性。

### M4（Major）按键释放
主张：触发热键的 Ctrl/Alt、确认的 Enter 若仍按下，可能影响注入；`SendInput` 不清空按键状态。
必改：增加“修饰键与确认键释放后才注入”的状态；处理 Enter KeyUp 泄漏；有限等待，不强行模拟释放。

### M5（Major）剪贴板
主张：“只备份 CF_UNICODETEXT”与“恢复”语义矛盾；原剪贴板可能是图片/文件/HTML。
必改：默认模式不碰剪贴板；兼容模式警示会替换；不宣称无损恢复；只提供显式“恢复先前纯文本”。

### M6（Major）成功率口径
主张：被设计为“只复制/拒绝”的宿主不能计入自动写入成功率；矩阵计数不一致。
必改：分 `AUTO_INSERT / COPY_ONLY / UNSUPPORTED`；自动成功率只统计 AUTO；错误窗口写入是测试阻断门，不是形式化保证。

### M7（Major）数据契约
主张：只写了 data.json 的备份协议；appRules 的 version/覆盖/损坏恢复缺失；`searchBlob` 含拼音但拼音在 M2。
必改：所有可变文件统一写入/备份/恢复协议；补 appRules 优先级；明确高版本回滚。

### M8（Major）UI 交付标准
主张：原生控件路线不等于能交付原型效果；缺尺寸、token、状态、DPI、截图验收。
必改：增加可检查的 UI Spec 与截图验收；不得以“原生控件受限”交付未设计界面。

### M9（Major）工期与单位
主张：M1 模块相加 20 而非 21，总数应为 32 而非 33；2,000 UTF-16 单元约等于 2,000 个 BMP 汉字，不是 1,000。
必改：统一工期表与总数；容量单位写明。

### M10（Major）输入过程边界
主张：单次 `SendInput` 不具备文本事务性；目标控件仍可能在注入中改变。
必改：M0 增加窗口销毁、控件替换、用户切窗、用户按键、程序退出等注入过程测试；长文本优先粘贴或复制。

### M11（Major）插入点判据
主张：`GetSelection()` 有范围不等于可编辑；普通编辑控件可能只有 `ValuePattern`；`TextPattern2.GetCaretRange()` 才是显式插入光标。
必改：分控件/宿主的能力策略；identity / editable / caret 分开报告；不支持的 API 标 UNKNOWN，不得冒充 VERIFIED。

### M12（Major）UIA 预算
主张：400ms 不是 COM 硬中断；单 worker 可能被长期挂起。
必改：UI 不阻塞、超时结果作废、过期快照不复用、队列不无限增长、worker 异常恢复；M0 故障注入。

### M13（Major）API 接受 ≠ 写入
主张：`SendInput` 返回全部事件只说明事件进入输入流。
必改：`useCount` 明确语义；不得显示“成功已验证”；部分输入不自动重试。

### M14（Major）覆盖率口径
主张：浏览器 UIA 覆盖率需要逐宿主/控件统计，不能凭白名单越过验证。
必改：给 `VERIFIED / IDENTITY_UNKNOWN / IDENTITY_MISMATCH / NON_EDITABLE / TIMEOUT / AUTO_INSERT / COPY_ONLY` 计数；产品降级由 M0 证据决定。
