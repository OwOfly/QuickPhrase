# QuickPhrase（快语）产品需求文档 PRD V1.1（含 UI 原型）

> 版本：V1.1｜日期：2026-11-18｜平台：Windows 10/11（x64）｜定位：单机、离线、轻量级全局快捷短语输入器｜状态：可用于 PoC 与 MVP 开发

## 1. 需求定义

### 1.1 一句话定义

用户提前维护常用文本；在浏览器、聊天工具、编辑器等软件的输入位置按全局快捷键，弹出可搜索的短语面板；通过键盘或鼠标选择后，将文本写入**触发前原输入位置**，随后面板消失。

### 1.2 需求中的关键区别

- **不是记事本**：使用时不必打开独立主窗口并手动复制。
- **不是剪贴板历史**：内容是主动维护、长期复用的短语；默认不采集剪贴板历史或键盘输入。
- **不是输入法**：不接管中文输入法，尽量不改动现有输入习惯。
- **不是全局文本替换**：MVP 只在用户明确唤起并选择后输入，不在后台监测按键并自动扩展缩写。

### 1.3 目标用户与典型场景

个人高频输入：客服回复、常见问题、代码/SQL 片段、邮件措辞、工单说明、项目模板、命令行片段。核心价值是“少切换、少打字、不输错”。

## 2. 产品原则与目标

1. **键盘优先**：不离开原工作流，快捷键 → 搜索 → 回车完成。
2. **正确性优先于速度**：目标窗口不明确时停止自动输入，不能盲目向当前窗口发送文本。
3. **默认不影响剪贴板**：优先采用 Unicode 文本输入；存在兼容问题才由用户主动切换粘贴模式。
4. **离线、本地、无账号**：不依赖网络，不上传短语，不监控键盘历史。
5. **低干扰**：常驻托盘、不常驻大窗口、不抢任务栏焦点；退出后不留钩子。
6. **先打通闭环再完善视觉**：技术 PoC 先验证热键、焦点恢复与跨应用输入。

### 2.1 非目标（V1.0 不做）

云同步、团队协作、AI 改写、富文本/图片输入、自动扩展缩写、批量宏执行、读取当前输入框文字、OCR、移动端、浏览器插件、敏感凭据保险箱。

## 3. 端到端用户流程

1. 首次运行：程序显示托盘图标，引导创建第一条短语（示例标题“项目日报”，正文“今日完成：\n待处理：\n风险：”）。
2. 日常输入：在微信、Chrome、VS Code 或记事本等输入框中定位光标。
3. 按 `Ctrl + Alt + Q`（可配置，冲突时提示），记录原前台窗口与焦点信息，然后显示轻量面板。
4. 面板搜索框自动聚焦；输入标题、正文关键词；使用 `↑/↓` 切换，`Enter` 选择，`Esc` 退出。
5. 选中时先关闭面板，尝试恢复并**校验原目标窗口/焦点**，仅在安全条件满足时插入短语。
6. 插入成功后回到原工作流；如果目标丢失，则停止自动输入，保留短语并提供“复制文本”作为退路。

### 3.1 行为约定

- **插入而非整框覆盖**：原输入框已有文字时，默认在光标处插入；若用户原本选中了一段文本，按目标软件的常规输入行为替换该选中区域。
- **触发不提交内容**：打开面板本身不得给原软件发送回车、空格或其他字符。
- **取消不修改**：`Esc`、点击面板外部或再次触发快捷键关闭面板，不写入文字。
- **不自动发送消息**：工具只负责输入，不代替用户点击“发送”。多行短语必须验证聊天类软件不会被换行误触发发送；有风险时使用兼容粘贴模式或提示。
- **非文本场景**：若没有可靠的可编辑目标，仍可查看、搜索和复制，但不能盲目模拟输入。

## 4. 界面与交互规范

### 4.1 快捷面板（核心界面）

- 参考尺寸：宽 460–520 px，高 320–400 px；圆角、浅阴影、无冗余边框，跟随 Windows DPI 缩放。
- 顶部：搜索框（默认聚焦）及占位符“搜索标题或内容…”；右侧可显示当前快捷键。
- 中部：结果列表，单项包含**标题**、正文 1–2 行预览、分类小标签；高亮当前结果；置顶项优先。
- 底部：键盘提示 `↑↓ 选择 · Enter 输入 · Esc 关闭`，可提供“管理短语”入口。
- 默认结果排序：置顶优先 → 最近使用 → 最近修改；输入关键词后，标题匹配优先于正文匹配。
- 无结果：显示“没有找到短语”，支持跳转新建；空库：显示新增指引。
- 唤起位置：优先尝试输入光标附近，若无法可靠取得位置，则显示在原窗口或当前显示器的合理位置，保证不越界；不因定位失败影响基本使用。
- 操作：单击结果可选择并插入；方向键导航；不强制使用鼠标；面板打开期间不重复叠加实例。

### 4.2 管理窗口（低频界面）

- 从托盘菜单“管理短语”打开，采用左侧分类、中间短语列表、右侧编辑区的简洁布局。
- 新建/编辑字段：标题（必填、1–80 字）、正文（必填、1–10,000 字，保留换行和缩进）、分类（可选）、是否置顶。
- 支持新建、保存、删除（二次确认）、复制为新短语、搜索、排序；所有变更即时保存。
- 支持 JSON 导入/导出，导入前预览条数及冲突处理（跳过/另存副本），不直接覆盖全部本地数据。
- 删除后提供短时间撤销提示；即使无法撤销，也可通过备份恢复。

### 4.3 系统托盘与设置

托盘菜单：`打开面板 / 管理短语 / 暂停快捷键 / 设置 / 退出`。设置项包括全局快捷键、开机启动（默认关闭）、输入方式（默认 Unicode，兼容模式需主动启用）、主题跟随系统、数据目录/备份导出。启动后不自动弹出管理窗口；使用互斥锁保证单实例。

## 6. 跨应用输入的技术与安全策略（重点）

### 6.1 窗口状态机

`IDLE → CAPTURED → PANEL_VISIBLE → RESTORING → INSERTING → IDLE`。任一步骤验证失败则进入 `FAILED_SAFE`：不输入、不把文本发到其他窗口，提示原因并给“复制文本”选项。

### 6.2 触发时保存什么

通过 Windows API 捕获原前台顶层窗口句柄、所属进程及线程、焦点控件线索、可能的光标位置与时间戳；弹窗之前完成快照。保存信息用于目标校验而非读取输入内容；不同框架（浏览器、Electron、终端）焦点信息可能不完整。

### 6.3 选择后的执行顺序

1. 阻止重复点击与重复快捷键，冻结选中的文本。
2. 隐藏面板；检查原窗口仍存在、属于预期进程，且未发生用户主动切换目标的冲突。
3. 请求回到原目标；确认实际前台窗口符合预期，再进行输入。仅凭 `SetForegroundWindow` 调用返回并不足以断言输入框已恢复。
4. 首选 `SendInput + KEYEVENTF_UNICODE` 注入纯文本；输入后释放所有模拟按键，避免遗留修饰键状态。
5. 无法可靠恢复或目标受到权限限制，则停止，不尝试向“此刻任意活动窗口”输入。
6. 发送输入事件后可记录使用次数，但不得仅凭 API 返回就断言目标应用已实际接收全部文本；统计失败时不能影响主流程。

### 6.4 输入方案取舍

| 方案 | 优点 | 主要问题 | V1 策略 |
| --- | --- | --- | --- |
| Unicode 模拟输入 | 不占用剪贴板、适合单行与一般文本框 | 特殊控件可能不接受；逐字符输入或换行存在兼容差异 | **默认方案** |
| 临时剪贴板 + Ctrl+V | 长文本及部分富编辑器兼容性更好 | 可能覆盖原剪贴板；多格式/延迟渲染不能保证完美恢复 | **手动开启的兼容模式** |
| 直接操作控件/UI Automation | 个别控件可定位或赋值 | 各应用实现差异大、权限与可编辑性复杂 | 不作为 P0 通用方案 |

**重要约束：** V1 不承诺对图片、文件、HTML 等所有剪贴板格式进行无损备份和恢复。兼容模式应先告知风险，尽力保存/恢复可处理的数据，并在检测到剪贴板被其他程序改变时避免强行覆盖；不能用固定延时就断言粘贴完成。不可自动在“Unicode 可能失败”后盲目重试粘贴，以免重复输入。

### 6.5 不支持或需降级的环境

- UAC 安全桌面、锁屏界面、部分管理员权限程序、游戏或受保护程序：不保证写入；默认不要求管理员权限，也不尝试绕过系统限制。
- 远程桌面、虚拟机、特殊中文输入法、终端、网页 `contenteditable`：需实机验证；可为特定应用采用兼容模式或只复制。
- 密码/受保护输入框：在可识别时阻止自动输入；由于跨软件识别并非百分之百可靠，需明确提示用户不要保存密码、Token、密钥等敏感文本。
- 多行消息：若目标软件将回车视为“发送”，不能因工具输入造成消息意外提交；列为专项测试并支持改用粘贴模式。

## 7. 数据结构与存储

**方案：本地 JSON + 原子写入 + 滚动备份。** MVP 规模预计几百至两千条短语，不必过早引入数据库。用户数据位于 `%LocalAppData%\QuickPhrase\`，与 EXE 分离，升级或替换 EXE 不丢数据；支持显式导出到任意文件夹。便携模式可在后续增加，避免默认把个人数据写到程序目录。

建议对象字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 稳定唯一主键 |
| title | string | 短语标题 |
| content | string | 原始正文，保留多行与空格 |
| category | string/null | 分类名，初版单分类即可 |
| pinned | boolean | 是否置顶 |
| sortOrder | integer | 同组手动排序预留 |
| createdAt / updatedAt | ISO-8601 | 创建、更新时间 |
| useCount / lastUsedAt | integer / ISO-8601 | 使用统计，可选字段兼容老版本 |

数据文件含 `schemaVersion`，保存时先写临时文件并校验，再原子替换；保留最近 5 个有效备份。首次启动生成空数据，不自动导入剪贴板。导入文件应校验大小、版本、字段和长度，阻止异常数据导致崩溃。

## 8. 非功能需求与指标

以下为**设计目标而非已经实测的性能**，在 PoC 阶段建立自动化或重复测量基线：

| 指标 | 目标 |
| --- | --- |
| 快捷面板显示延迟 | 常规 Windows 设备 P95 ≤ 150 ms |
| 1,000 条短语本地关键词检索 | P95 ≤ 50 ms |
| 程序冷启动至可响应热键 | ≤ 1.5 s |
| 常驻内存 | 以原生轻量方案为目标，空闲 ≤ 35 MB |
| EXE 发行包体积 | 以原生构建为目标，≤ 15 MB；不得为体积牺牲正确性 |
| 正文长度 | 单条 ≤ 10,000 字符；中文、Emoji、换行、缩进正确保留 |
| 网络和权限 | 核心功能完全离线、无需管理员权限、默认不开机自启 |
| 兼容性与正确性 | 在已声明支持的应用/输入模式测试矩阵中，成功写入率目标 ≥ 99%；错误目标写入为 0 容忍的发布阻断项 |
| 健壮性 | 非正常结束后重启可用；不会把文本输到错误窗口 |

## 9. 技术方案建议

### 9.1 推荐架构

为严格控制 EXE 体积和后台资源，正式版**优先评估 Rust + Windows 原生 Win32 API（`windows` crate）+ `serde_json`**。UI 可从系统原生控件起步，尽量不引入 Electron、Chromium、WebView2 和大型 UI 框架。模块划分：

- `hotkey`：注册、冲突检测、卸载全局快捷键。
- `window_context`：采集/恢复窗口与焦点、校验前台目标。
- `popup`：面板绘制、搜索、键盘导航和定位。
- `inserter`：Unicode 插入与可选兼容粘贴，失败安全退出。
- `snippet_store`：校验、原子存储、备份、导入导出。
- `tray_settings`：系统托盘、开机启动、设置、单实例。

### 9.2 备选及决策原则

| 技术 | 优点 | 代价 | 适用情况 |
| --- | --- | --- | --- |
| Rust + Win32 | 原生独立 EXE，资源与依赖可控 | 自定义 UI 和 Windows 互操作工作量较高 | **严格追求轻量，推荐基线** |
| C# + .NET 10 WinForms | Windows GUI 开发速度快、易调试 | 若打包自包含单文件，运行库使体积明显变大 | 以开发效率优先时选用 |
| AutoHotkey v2 | 做热键/插入原型最快 | 界面工程化、维护、发布与安全软件兼容需额外验证 | 用于极早期 PoC |

不要同时开发多条产品技术线。**先用选定技术完成“热键 → 弹窗 → 正确回填”的技术验证**；若该关键路径无法稳定通过，暂停 UI 与管理功能开发并调整路线。

## 10. 关键异常与边界处理

| 情况 | 期望行为 |
| --- | --- |
| 快捷键被其他软件占用 | 注册失败提示并要求修改，不静默失效 |
| 面板显示期间切换应用/原窗口已关闭 | 不自动输入，允许复制当前短语 |
| 原焦点丢失、用户选中文本发生变化 | 尽最大努力恢复原焦点；不确定则停止，不破坏已有输入 |
| 用户按 Esc/点击外部 | 面板关闭，不修改原输入框 |
| 多屏幕、不同缩放、屏幕边缘 | 弹窗可见，位置不越界，切换屏幕无残留窗口 |
| 中文输入法组合态（候选词未提交） | 不吞词、不乱序；必要时提示先完成输入法组合 |
| 全角符号、Emoji、SQL 多行文本 | 文本内容保持准确；有差异时告知输入模式兼容限制 |
| 剪贴板被占用或其他软件修改 | 兼容模式给错误反馈，不无限重试、不强行覆盖新剪贴板 |
| 短语数据损坏/磁盘不可写 | 保留已有数据并提供恢复入口，不用空数据覆盖原文件 |
| 反复打开、连续双击、多次按热键 | 保证只有一个面板、一次插入动作 |
| 杀毒软件/权限隔离拦截注入 | 清晰反馈不支持，不提权绕过 |

## 11. 开发里程碑与交付标准

### M0：可行性验证（必须最先完成）

最小托盘程序：注册热键、捕获前台窗口、弹出 3 条固定短语、回到原控件插入中文/英文/换行。覆盖记事本、Chrome/Edge、VS Code、至少一种聊天软件；验证管理员目标、切换窗口、中文输入法、多屏 DPI。产出**兼容性表 + 失败原因 + 技术路线结论**。

### M1：MVP（首个可用版本）

完成本地 CRUD/分类/置顶、搜索与导航、托盘、设置、持久化备份、导入导出、双输入模式、错误反馈。提供 Windows x64 EXE、README、数据目录说明、安装/卸载与升级说明。可以不做安装包，采用解压即用/单 EXE 发放，是否真正免运行库按所选技术验证。

### M2：体验增强（基于真实使用反馈）

最近使用排序、拼音检索、快速新增、单应用输入模式、变量模板、便携模式、主题细节与高 DPI 优化。

## 12. MVP 验收用例（发布阻断项）

1. 在记事本光标中间插入中文“您好，感谢反馈”，文字位置正确，原前后文本不丢失。
2. 在 Chrome 普通输入框、网页多行文本域、VS Code 编辑器重复上述步骤，重点验证 Unicode/换行。
3. 选中原文本后插入，遵循原应用的正常“替换选区”行为，不能全框清空。
4. 打开面板后按 `Esc`，原输入框内容不变。
5. 打开面板后切换到另一应用再选择短语，不得错误输入到另一应用。
6. 在多屏不同 DPI 与屏幕边缘，面板始终可见且不失焦。
7. 在中文输入法候选态触发、输入含 Emoji 和多行 SQL，文字无截断、乱码和意外提交。
8. 其他软件占用快捷键时有明确报错，修改后生效。
9. 新增 500–1,000 条短语，搜索流畅；关闭和重启后内容、分类、置顶状态一致。
10. 兼容模式启用前有剪贴板风险提示；失败时不覆盖其他程序刚复制的新内容。
11. 以普通权限运行时，对管理员窗口/安全桌面不静默错误注入。
12. 连续快速触发 20 次，仅处理预期的每次选择，无重复发送、卡死或孤儿进程。

## 13. 最终产品边界与开发指令

**第一版只要把 3 件事做到可靠：**① 用户能方便地维护文本；② 任意普通输入框前用热键快速选中；③ 内容准确进入原输入位置。管理界面可以朴素，跨软件输入绝不能“看似成功但输错位置”。

**开工顺序：**先做 M0 并提交测试结果；M0 通过再进入 M1；每个模块独立可测，重点为焦点管理、Unicode 插入及数据安全写入。不得先完成漂亮界面再补关键输入能力。


## 14. 高保真 UI 原型与视觉设计规范（V1.1 新增）

### 14.1 原型交付

- **整体高保真设计图：** ![QuickPhrase 高保真界面总览](a_high_fidelity_product_design_mockup_ui_prototy.png)
- **可交互 HTML：** [QuickPhrase 交互原型 V1.1](QuickPhrase_交互原型_v1.1.html)（可使用浏览器本地打开，无外部依赖）
- HTML 中的原应用文本框仅模拟“原位输入”，不能在浏览器中实现跨 Windows 应用输入；正式 EXE 需按第 6 章实现并测试。
- 设计图用于呈现风格、布局与视觉比例；若图中微小文本或标注与本文档不一致，**以本 PRD 的交互规格和字段名称为准**。

### 14.2 视觉方向

**现代简洁、轻盈克制、接近 Windows 11 Fluent 的高级感**：浅灰白背景、轻微毛玻璃视觉、紫蓝强调色、低对比细边框、柔和阴影、12–20 px 圆角。避免大面积饱和渐变、夸张图标和厚重卡片。优先确保文字清晰、操作效率与小尺寸表现。

| 设计 Token | 默认值 | 用途 |
| --- | --- | --- |
| Primary | `#7655E9` | 选中、核心按钮、焦点 |
| Primary hover | `#5E45D7` | 按钮悬停与按下态 |
| Page background | `#F5F6FB` | 管理窗口背景 |
| Card background | `#FFFFFF` | 面板与编辑器背景 |
| Heading | `#22243E` | 标题和核心文字 |
| Secondary text | `#777D92` | 描述与辅助提示 |
| Border | `#E9EBF3` | 低对比区块分割 |
| Selection | `#F0EDFF` | 短语选中项 |
| Success | `#22C55E` | 已成功保存/明确成功事件 |
| Warning | `#F59E0B` | 可恢复异常、兼容模式提示 |
| Error | `#EF4444` | 保存失败、验证失败 |

字体使用 Windows 系统 UI 字体优先级：`Segoe UI Variable`、`Microsoft YaHei UI`、系统无衬线；中文 12–14 px 常规正文、15–17 px 小标题、18–22 px 界面标题。鼠标可操作区建议不小于 32×32 px，主要按钮 36 px 左右。需要键盘焦点高亮；不能只通过颜色表达选中状态。

### 14.3 界面 A：快捷面板（P0 核心）

**目标尺寸：** 宽 520 px，初始高度约 420 px；允许在 460–540 px 和 320–470 px 范围内按内容与 DPI 调整。优先以真实 Win32 物理/逻辑坐标转换实现多屏定位，确保无越界。

**布局自上而下：**

1. 搜索区（高度约 62 px）：搜索图标 + 搜索输入框 + 快捷键提示 + 设置入口；弹出立即聚焦搜索。
2. 分类栏（约 46 px）：`全部 / 工作沟通 / 客服回复 / 开发相关 / 个人常用`，宽度不足允许横向滚动；类别数量由实际数据决定，不写死。
3. 短语结果区（剩余空间，内部滚动）：左侧 36 px 类型图标，中间标题与一行正文预览，右侧分类标签。单项高度建议 64–70 px。默认第一个结果高亮。
4. 操作说明区（约 42 px）：`↑↓ 选择`、`Enter 输入`、`Esc 关闭`、`管理短语`。管理入口点击后应切换到管理主窗口并取消本次插入上下文。

**交互状态：** 默认列表、实时搜索、无结果、空库、焦点丢失、无法恢复原输入框、重复热键、加载失败。搜索结果关键词应高亮但不得修改实际文本；类别切换后选中项重置为首个；选择后弹窗立即消失，插入成功不弹阻断式对话框；失败时轻提示并提供“复制文本”按钮。

### 14.4 界面 B：短语管理（P0）

**建议初始窗口尺寸：** 1040×650 px，最小 800×540 px，支持窗口缩放与 DPI 调整。

**三区结构：**

- 左栏（170–190 px）：`全部`、各分类、回收站预留；当前分类背景高亮，显示数量。MVP 的回收站若未落地，不应呈现不可用入口。
- 中栏（260–290 px）：`新增 / 导入 / 导出` 工具栏、搜索框、短语列表；点击切换当前编辑对象。
- 右栏（剩余宽度）：标题、正文多行文本框、分类下拉、置顶开关、`取消/保存`。支持键盘 Tab 顺序与未保存变更确认。

**必须落实的状态：** 新建、编辑、校验失败（空标题/空正文/过长）、保存成功、保存失败、重复标题、删除确认、未保存离开拦截、导入冲突、备份恢复。

### 14.5 界面 C：设置（P0）

将高频设置集中在一个简单列表中，包含全局快捷键（支持记录与冲突提示）、文本输入方式（默认 Unicode、兼容粘贴须二次确认风险）、开机启动（默认关闭）、界面主题（跟随系统/浅色/深色）、数据与备份路径。每一项需有当前状态和简短的说明文案，不让用户猜测开关的作用。

### 14.6 界面 D：托盘菜单（P0）

双击托盘图标打开管理窗口；右键菜单包含：`打开快捷面板`、`管理短语`、`暂停快捷键/恢复快捷键`、`设置`、`关于`、`退出`。退出必须确实注销全局快捷键并安全释放资源。普通关闭管理窗口仅隐藏窗口，托盘继续运行。

### 14.7 动效与易用性约束

- 弹出/隐藏动画建议 100–140 ms，轻微透明度 + 位移；启用系统“减少动态效果”时关闭动效。
- 搜索和方向键导航不应触发明显卡顿，不需要每次弹窗渲染复杂的磨砂模糊。
- 浅色/深色两个主题均须验证正文、选中态和提示文字的对比度；支持 Windows 125%、150%、200% DPI。
- 不要求联网、不加载远程字体，不依赖 WebView2；视觉风格可以采用原生绘制或轻量 UI 实现，**不能为了复现 HTML 阴影而破坏原定性能目标**。
- 中文 IME 组合输入期间，`Enter` 用于确认候选词时不得被误判为短语选择；组合完成后 Enter 才触发插入。

### 14.8 设计验收与开发交付

| 编号 | 验收内容 | 判断标准 |
| --- | --- | --- |
| UI-01 | 视觉统一 | 同一组件跨面板、管理、设置使用一致的颜色、字体、间距、圆角与按钮状态 |
| UI-02 | 快捷面板 | 支持搜索、滚动、选择、取消、空态与键盘操作；无重复窗口 |
| UI-03 | 管理编辑 | 新增、编辑、删除、置顶、分类切换、导入导出入口清晰 |
| UI-04 | 键盘导航 | 搜索获取焦点，方向键/Enter/Esc 可用；IME 组合无误触 |
| UI-05 | 多屏和高 DPI | 屏幕边缘正确定位；125%/150%/200% 无截断、遮挡与模糊 |
| UI-06 | 无障碍 | 键盘焦点可见、文字对比度达标、主要控件可访问 |
| UI-07 | 性能守恒 | 常驻内存/热键弹出延迟不能因 UI 方案明显超出第 8 章目标 |
| UI-08 | 设计一致性 | 依据高保真原型检查整体节奏与状态，但文案、交互和安全始终以 PRD 为准 |

**实施顺序不变：** M0 先跑通可靠的跨软件输入；M1 建立完整管理与设置功能；在同一技术栈内按此原型实现 UI。不得将 HTML 预览当作正式桌面 UI，也不得为了视觉效果绕过输入安全验证。
